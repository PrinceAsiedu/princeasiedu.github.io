ipxis — self-hosted secure delivery homelab

A Debian homelab running Gitea, Woodpecker CI, Zot, Authentik, OpenBao, and Ollama under Podman, used to own a secure software delivery pipeline end to end.

Overview

ipxis is a self-hosted Debian homelab built to answer one question: how much of a secure software delivery pipeline can be owned end to end without depending on opaque hosted services?

It runs Podman workloads for Gitea, Woodpecker CI, Zot, Authentik, OpenBao, and Ollama, and it has been the primary lab for exploring artifact signing, SBOM generation, and registry verification workflows in software supply-chain security.

Problem

Most small engineering groups and open-source communities depend on hosted CI and registry services whose internals they cannot audit. If you care about software provenance rather than just passing a CI job, you need a place where you can inspect every step: how a build is triggered, what an artifact contains, how it was signed, and who was allowed to verify it.

Role

Author and operator. Design and day-to-day operation of the platform: service wiring, identity, secret management, CI federation, and the security workflow layered on top.

Architecture

  • Orchestration: Podman on Debian for container workloads.
  • Source: Gitea as the Git host.
  • CI: Woodpecker CI — a pull request triggers a build.
  • Registry: Zot hosts OCI artifacts locally.
  • Identity: Authentik provides authentication and access policy.
  • Secrets: OpenBao stores and issues secrets used by pipelines.
  • Local inference: Ollama provides local analysis for parts of the pipeline.

Engineering

The chain of evidence between components is the useful part of the system, not any single tool:

  1. A pull request triggers a build in Woodpecker.
  2. The build produces an SBOM with Syft.
  3. The SBOM is scanned with Grype and the results archived.
  4. The image is signed with Cosign and pushed to Zot.
  5. Verification happens as a normal release step.

Secrets come from OpenBao; identity is enforced through Authentik; every step stays inside infrastructure that can be audited.

Security

  • Artifact signing: every image is signed with Cosign before promotion; unsigned artifacts are treated as incomplete.
  • SBOM + diffing: Syft output is diffed build-to-build so Grype review focuses on what actually changed.
  • Self-hosted identity and secrets: Authentik and OpenBao keep trust boundaries inside the lab.
  • Zero-trust networking evaluation: NetBird vs Tailscale was evaluated for remote access as part of the wider platform story.

Challenges

Running a full supply-chain toolchain on a single host means resource competition, version drift between self-hosted components, and carrying the operational burden of services that a hosted provider would normally absorb. Each of those is deliberate — the point is to feel what small teams feel when they adopt these patterns.

Decisions

  • Self-host rather than managed where trust matters more than convenience.
  • Podman over a full Kubernetes cluster to keep the lab approachable and aligned with the smallest realistic deployment.
  • Local Ollama over external AI APIs for analysis steps that should stay inside the lab.

Results

This lab is the basis of the writing on this site. The pattern — know what you built, know what is inside it, know who approved it, make verification the default — is directly informed by operating this system.
